# main-chat UX rules

## 目的
main-chat は **「AIに仕事を頼む入口」** であり、画面設計は **チャット体験を最優先**する。

## 基本方針（固定）
- **main-chat はチャット体験を優先**する（フォーム画面化しない）。
- 送信後は **最下部へ自動スクロール**する。
- **AI返答後も最下部へ自動スクロール**する。
- 入力欄は **下部固定**（キーボード表示でも入力が埋もれない）。
- 1回に聞くことは **1つ**（追質問は最小単位で分割する）。
- 不要な長文説明を避ける（**結論→次の1アクション** で短く）。

## 聞く内容（初期MVPの制約）
- 「明日の予定」は **初期MVPでは聞かない**（運用定着までノイズを増やさない）。

## 状態の見える化
- ユーザーが **今どの段階か分かる**ようにする。
  - 例: 「現場選択 → 日報入力 → 保存確認」など
  - 例: 「見積 Phase1/Phase2」など

## 迷子対策
- 「どこ押せばいいか分からない」を減らす。
  - 迷子になりそうなタイミングでは、次に押すべき導線を **1つだけ**提示する。
  - 画面遷移が必要な時は、遷移先を明示する（例: `/project-selector`）。

## 実装メモ（運用ルール）
- UXの“例外”を増やさない（ルールベース/最小実装を優先）。
- 既存 Must 導線（現場/日報/経費/売上/履歴/請求書）を壊さない。
